# v1.11 — Handoff and development safeguards

**Baseline:** v1.10 Patch 5 main f08e894ca6713d0828cf4739d33cd87ac0da46fa; original 15 source/doc files backed up under backups/v1.10-final/.

**Current UI:** Shared Play/Pause/Reset, HR, Timeline and 3 scenario presets; original ECG Monitor remains visible in all cases; Electrical/Mechanical/Wiggers show one selected visualization; side-by-side desktop learning inspector becomes stacked on narrow screens; optional Wiggers desktop focus and full six-part nursing/physiological disclosure.

**Technical architecture:** Original script.js is sole driver for A physiological/B visualization clocks and ECG sampling; mechanics.js owns the native Mechanical/Electrical model, wiggers-view.js and profile own original Wiggers SVG/relative values, wiggers-learning.js owns clinical/nursing wording. New dashboard-v111.js is presentation only and runs last, relocating original DOM and exposing the UI-only CardiacDashboard.sync adapter. No new rAF, timer or domain-state source.

**Regression and QA:** Retain all eight original v1.8–Patch5 suites and the new tests/test_v111.py. The real-page test checks view selection, canonical A/B equality, manual/preset HR, Reset/Play/Pause/seek, help focus/keyboard, Wiggers focus and responsive widths 1440/1366/1024/768/390/360. The separate Capture v1.11 Actual UI Screens workflow produces desktop/mobile screenshots. Human physical-device checks remain required.

**Clinical restrictions:** Educational relative pressures are not mmHg, normalized volume is not mL/EF/CO, sound markers are not audio, high-HR QTc remains an approximation, and the two existing Mechanical/Wiggers exact valve boundary conventions have minor tie differences. Distinguish electrical and mechanical activity in the inspector.

**Future/out-of-scope ideas:** consistent localization, beginner/advanced educational levels, additional validated arrhythmia and disease models, optional side-by-side comparison on wide monitors. These require independent design and medical review; do not silently add them as a side effect of UI refactoring.

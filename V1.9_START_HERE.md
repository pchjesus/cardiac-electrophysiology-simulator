## Main goal — Cardiac Cycle & Hemodynamics

Extend the same physiological cycle (A clock) with:
1. Electrical-to-mechanical delay and atrial/ventricular contraction.
2. Ventricular filling, isovolumetric contraction, ejection and isovolumetric relaxation.
3. AV/semilunar valve state driven by simplified pressure differentials.
4. Chamber filling/ejection visual states.
5. Blood-flow directions and flow visualization linked to the ECG.

## Existing v1.8 timing architecture

- A = physiological elapsed time, HR-dependent RR and ECG event boundaries.
- B = visualization clock with the user-approved v1.7-derived HR-to-animation-speed calibration.
- One requestAnimationFrame loop; no competing timers.
- `getPhysiologicalTiming(hr)` provides P/QRS/T/AV/His/Purkinje event timing; `getPhysiologicalCyclePhase()` resolves the active beat phase.
- The ECG waveform, measurements, conduction, Current Phase, event labels and Timeline already consume A via this engine.

## Non-negotiable requirements

- Preserve ECG, conduction (including simultaneous RBB/LBB), measurements, Explanation, Current Phase, ECG Event, Timeline, HR slider and Play/Pause/Reset.
- Preserve B visual pacing unless the user explicitly approves a change.
- Add mechanical/hemodynamic timing as a new model consumer of A (never canvas pixels or separate `setTimeout` loops).
- Make clear that electrical depolarization, pressure change, valve state and blood flow are causal but not simultaneous.
- Treat all mechanical/pressure values as educational approximations, not clinical measurements.
- Follow small-patch design/risk review → implementation → integration + regression tests → backup/versioning.

## Known limitations / design checkpoints

- HR >140 bpm: current SA-first ECG model clips QT to keep the waveform in one non-overlapping cycle. Before using the QT end as a mechanical cycle landmark, decide whether to support overlapping events/beat-history.
- QTc uses Bazett and can be biased at rate extremes; model QT is not patient-validated.
- 390px mobile viewport has inherited ~47px horizontal overflow; leave alone unless an explicit UI patch is approved.
- v1.8 automated tests passed; user physical browser acceptance remains pending.

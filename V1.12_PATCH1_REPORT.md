# v1.12 Patch 1 — Guided Learning foundation

**Status:** Narrow implementation of user-approved A/A/A UX. Full v1.12 remains IN PROGRESS; this is not a clinically validated FINAL release.

## Approved behavior and scope

1. **A / existing inspector:** An unobtrusive "5단계 학습" button in the existing learning-inspector title opens an optional lesson in the same space, replacing—not stacking beneath—the original short clinical summary. Closing restores that original summary and leaves the separate full six-part nursing explanation untouched.
2. **A / reading-only step navigation:** Patch 1 provides a native dropdown for the five stages. Selecting a study stage only changes educational content; it never seeks the Timeline, pauses, changes HR, or changes physiological clock A / visualization clock B.
3. **A / manually selected Wiggers:** The guide does not automatically switch the current Electrical/Mechanical/Wiggers visualization. Explicit guide buttons for Wiggers view and Timeline seeking are **deferred to Patch 2**.
4. **Clinical content:** The new CardiacLearning.getStageNarrative(stageId) exposes original PHASES and RATE wording read-only. guided-content.js reads unmodified Mechanical interval boundaries, validates representative midpoints against Wiggers snapshot stages and distinguishes the *model RR later-segment* filling from initial flat filling (relative volume 0.88). No actual mmHg/mL/EF/CO or patient-state inference.
5. **No extra animation clock, state source or DOM clone.** guided-learning.js is loaded after dashboard-v111.js and owns only lesson open/selected-stage UI state. Dashboard invokes an optional read-only sync during its existing loop; while closed the guide returns immediately.

## Explicit non-goals

Patch 1 deliberately excludes previous/next buttons, Wiggers view buttons, explicit guided Timeline seeking, basic/advanced toggle, the 10 questions and completion scoring. Patch 2 owns user-triggered viewing/seek/navigation, Patch 3 owns difficulty and quizzes. Both will require separate code review, tests and PRs.

## Risks and acceptance

- Default 1366×768 layout: v1.11.1 documented 892px baseline. Test no more than 908px at initial Ready, and visually inspect desktop/mobile. No large permanent guide card.
- Model interpretation: electrical and mechanical events differ, five mechanical stage labels are educational. *Model RR later-segment filling* is not clinical late-diastolic filling. Initial RR filling relative volume flat 0.88 remains an explicit known simplification.
- State isolation: no guided buttons may mutate A/B, HR, playback or current visualization tab. All former six-part clinical explanation text must remain available and Wiggers/ECG chart reading unaffected.
- Actual target-device acceptance remains pending even if Chromium CI passes.
